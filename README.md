# 🪙 Монетки

Внутренний офис команды: клиенты, задачи, финансы, корты и сотрудники в одном месте.

**Сайт:** https://owl-14.github.io/monetki (работает как приложение — ставится на телефон)

## Что умеет

- **Любое количество бизнесов** — администратор создаёт их в разделе «Ещё», а доступ и изоляция задаются через memberships. Прежние 🎾 Падел (`padel`) и 💻 Разработка (`dev`) остаются без изменений.
- **Динамические модули** — переключатель и меню строятся из карточек доступных активных бизнесов. В «Ещё» администратор настраивает название, значок, модули, доли и доступы, а также архивирует и восстанавливает бизнесы без удаления данных.
- **События для любого бизнеса**: список и календарь мероприятий, карточка с обзором, участниками, экономикой и историей изменений самого события и фиксации расчёта. Участником может быть игрок, CRM-контрагент или контакт; место и ресурс задаются универсально, без привязки к паделу.
- **Падел**: площадки с календарём кортов (будни 18:00–23:00, статусы «забронировано / свободно / занято / хотелось бы» + цена часа), база игроков с импортом из Excel.
- **Склад**: несколько складов, каталог расходников, рассчитанные из движений остатки и резервы, приход, списание, перемещение и инвентаризация. Закупку можно связать с финансовой операцией, но расход в финансах автоматически не создаётся.
- **Разработка**: клиенты с воронкой (Лид → Переговоры → В работе → Поддержка → Отказ).
- **Задачи**: админ ставит любому, сотрудник — только себе; статусы «Не видел» (красный) → «В работе» → «Выполнена» / «Есть вопросы»; обсуждение внутри задачи; уведомления.
- **Финансы** (только админы), вкладки:
  - *Необработанные* — очередь Точка Банка до назначения бизнеса; внутри есть **Очередь / Настройки / Журнал**, ручное проведение и безопасные правила-подсказки;
  - *Операции* — доходы/расходы по месяцам или за всё время, автоматическая выписка из Точка Банка каждый час, остаток счёта, способ оплаты (счёт/карта/СБП/наличные);
  - *Траты* — траты сотрудников с обязательным фото чека; возврат со счёта или из наличных;
  - *Счета* — личные счета владельцев: (доходы − расходы) направления по долям (Разработка 50/50; Падел 34/33/33), персональные расходы;
  - *Наличные* — кассы Саввы и Андрея, отдельно от общей статистики.
- **Зарплата**: со счёта или наличными, с зачётом непогашенных трат сотрудника; у сотрудника — раздел «Деньги» с историей выплат и трат.
- **Темы**: светлая / тёмная / как в системе.

Чтобы включить события, администратор открывает **Ещё → Бизнесы, роли и доступы**, отмечает модуль **События** у нужного бизнеса и нажимает **Сохранить бизнес**. После этого в меню появится одноимённый раздел. Сначала нужно создать тип события, затем само событие и участников.

Фактические оплаты, депозиты, расходы и возвраты в событии не создают второй денежной записи: администратор привязывает уже существующую операцию из раздела «Финансы». Такая связь сохраняется один раз и после этого не редактируется. Когда событие завершено или отменено и все поздние оплаты учтены, кнопка **Зафиксировать расчёт** сохраняет итоговую прибыль, маржу и доли владельцев. Импорт 79 исторических событий в эту версию намеренно не входит: пустой раздел не заполняется вымышленными данными.

### Правила банковских операций

Администратор открывает **Финансы → Необработанные** и нажимает хорошо заметную кнопку **Настройки правил/скриптов** — она ведёт к правилам, автоматизации и журналу и остаётся полноширинной на телефоне. В редакторе доступны направление, сумма, способ, имя, полный телефон/ИНН отправителя или получателя, назначение, владелец расхода, контрагент и связи с игроком, CRM или событием. Правила могут предложить или, при строгом однозначном совпадении, автоматически назначить бизнес/категорию и связи. Автопроведение изначально выключено и включается только отдельным подтверждением после проверки очереди и задания лимитов. Совпадение только по сумме никогда не проводится автоматически; конфликт, неизвестный или маскированный признак всегда оставляет операцию для человека. На карточке операции есть **Создать правило**, старое ручное **Назначить → Провести операцию** остаётся доступным, а удаление правила переносит его в архив с сохранением версий.

Во вкладке **Журнал** видны безопасные результаты без банковских идентификаторов, реквизитов, телефонов, ИНН, имён и сумм. Проведённая банковская операция в общем списке открывается только для чтения; категория, способ, владелец, контрагент и комментарий исправляются через журнал, где сохраняется история. **Безопасно отменить** возвращает операцию в очередь лишь пока финансовая запись и её неизменяемые связи не менялись; иначе приложение попросит сделать компенсирующую ручную операцию.

Сотрудник не видит ставки, взносы участников, прибыль и доли: ему доступно только собственное начисление по тем событиям, где он ответственный. После фиксации расчёта это начисление берётся из неизменяемого снимка и уже не зависит от последующего изменения типа события. Используемого участника или площадку нельзя удалить из справочника, пока ссылка нужна истории.

Кнопка **Ещё → Скачать копию** запускает отдельную админскую backup-операцию. В файл входят также события архивных бизнесов, данные при выключенном модуле, история банковских правил с очередью и фото чеков; обычная загрузка интерфейса по-прежнему показывает только разрешённые активные данные. Повторное восстановление той же копии безопасно, а конфликт с уже зафиксированной event- или банковской историей останавливает соответствующий граф без частичного переписывания.

## Как устроено

| Часть | Технология |
|---|---|
| Интерфейс | статический сайт (HTML/CSS/JS без сборки), PWA, GitHub Pages |
| Сервер | Supabase Edge Function (`supabase/functions/api/index.ts`) |
| База | Supabase Postgres (таблица `records` c JSON-записями, включая `businesses`, `memberships`, `businessOwners`), закрыта RLS |
| Банк | API Точка Банка: выписка + баланс, синхронизация по расписанию |
| Деплой | merge в `main` → Pages (фронт) + GitHub Action (бэкенд) автоматически |

Вход — по личному 6-значному коду сотрудника (выдаётся в разделе «Команда»).
Без подключённой базы сайт работает в демо-режиме на localStorage.

## Совместимость данных

- ID прежних бизнесов остаются `padel` и `dev`; новые получают безопасный служебный ID автоматически из названия.
- Архивирование меняет только статус бизнеса: карточка, доступы и связанные записи сохраняются для восстановления.
- Новые и обновлённые бизнес-записи содержат одинаковые `businessId` и `unit`.
- Старые резервные копии и строки только с `unit` продолжают работать: при первом входе/bootstrap сервер идемпотентно создаёт CORE-записи и дополняет область бизнеса.
- Доли по умолчанию не изменились: Разработка 50/50; Падел 34/33/33. Расчёт «Счетов» читает `businessOwners`, а при их отсутствии использует прежний встроенный справочник.
- У нового бизнеса создатель автоматически получает 100% доли; её можно перераспределить в карточке бизнеса. Тип события может переопределить эти доли, но итог всегда должен составлять 100%.
- Старые данные продолжают работать без сущностей событий. Миграция только включает модуль `events` для legacy-бизнеса `padel`; исторические турниры и денежные расхождения автоматически не импортируются.

